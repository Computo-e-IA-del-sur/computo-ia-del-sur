关于 Supabase 的一切：版本与差异

Cómputo e IA del Sur
2026年8月

为什么要了解 Supabase？

Supabase 已成为 Firebase 最可行的开源替代方案之一。它建立在 PostgreSQL 之上，提供强大的关系数据库，以及身份验证、存储和实时 API。在本文中，我们将分析其架构、不同计划（Free、Pro、Team 和 Enterprise）的特点，以及与自托管安装相比，使用其云服务的运营优势。

什么是 Supabase？

Supabase 将自己定义为成立于2020年的开源后端即服务（BaaS）平台。它通常被呈现为 Firebase 的开源替代方案，但基于 PostgreSQL 的技术力量。每个项目都包括一个专用的 PostgreSQL 实例，可以完全访问高级 SQL、表关系以及 PostGIS、Pgvector、pg_cron 等强大的扩展。

实际上，Supabase 在一个仪表板中集中了最常见的后端服务：数据库管理、用户和身份验证系统、文件存储、自动 API 生成（REST 和 GraphQL）以及边缘函数执行。这使开发人员能够利用 PostgreSQL 的稳定性以及敏捷工具来加速开发。

Supabase 架构

Supabase 的内部架构基于多个与中央 Postgres 数据库通信的开源服务。在官方平台上，每个项目都有自己完整的 PostgreSQL 数据库（无抽象）。此外，Supabase 集成了多项服务（GoTrue 用于 Auth，PostgREST 用于 API，Realtime，Storage 等）。

托管计划与版本

Supabase 提供托管的云服务模式，旨在通过不同层级支持任何项目的发展。

Free

$0 /mo

个人项目、原型和学习的理想选择。

  • 最多2个活跃项目
  • 50,000 MAU
  • 500 MB 数据库
  • 闲置7天后暂停
最受欢迎

Pro

$25 /mo

适用于中小型生产应用。

  • 无限项目
  • 基础 100,000 MAU
  • 8 GB 数据库
  • 不会因闲置暂停

Team

$599 /mo

面向需要扩展性和合规性的公司。

  • 包含 Pro 计划所有内容
  • SOC2 和 ISO 27001
  • 优先支持 (SLA)
  • 企业 SSO

Enterprise

定制

为互联网规模工作负载提供的专用基础设施。

  • 专用基础设施
  • 符合 HIPAA
  • 24x7 高级支持
  • BYO 云部署

部署模式：优缺点

托管平台

在 supabase.com 上的标准使用，由官方团队管理。

优点

  • 自动配置和扩展
  • 即时更新和新功能
  • 高可用性，由 Supabase 负责维护

缺点

  • 依赖外部服务
  • 基于使用的成本和美元定价

本地开发 (CLI)

用于在本地启动服务的 CLI 工具。

优点

  • 快速且 100% 免费的开发
  • 离线工作和完全的数据隐私
  • 自动化测试 (CI/CD) 的理想选择

缺点

  • 不适合生产环境（技术栈未加固）
  • 没有高级托管服务或真实的 Web 仪表板

自托管

在自有基础设施（如 Docker、AWS、GCP）上安装。

优点

  • 完全的数据主权以符合合规性
  • 没有 Supabase 平台的月度费用
  • 根据精确规模进行细粒度硬件调整

缺点

  • 高运营负担（DevOps、备份、安全、宕机）
  • 没有分支、没有分析仪表板、也没有自动恢复

结论与建议

对于测试阶段、原型或学习项目，Free 计划和本地 CLI 开发免费满足基本需求。随着项目向生产阶段扩展，Pro 计划（25美元/月）通常是最合理的步骤，因为它提供了充足的资源，并减少了开发团队的运营负担。另一方面，具有严格安全和认证要求的公司将在 Team 计划中找到价值。

在大多数情况下，托管云版本被证明是委托基础设施维护的最实用选择。自托管模式虽然避免了平台成本，但涉及承担所有操作（备份、监控和更新）的全部责任，因此主要在特定的技术或法律要求阻碍使用第三方解决方案时建议使用。
