Todo sobre Supabase: Versiones y Diferencias

Cómputo e IA del Sur
Agosto 2026

¿Por qué deberías conocer Supabase?

Supabase se ha consolidado como una de las alternativas Open Source más viables frente a Firebase. Al estar construida sobre PostgreSQL, ofrece una base de datos relacional robusta junto con herramientas de autenticación, almacenamiento y APIs en tiempo real. En este artículo analizamos cómo está estructurada su arquitectura, qué características incluyen sus distintos planes (Free, Pro, Team y Enterprise) y cuáles son las ventajas operativas de utilizar su servicio en la nube en comparación con mantener una instalación propia (Self-Hosted).

¿Qué es Supabase?

Supabase se define como una plataforma Backend-as-a-Service (BaaS) de código abierto creada en 2020. A menudo se presenta como una alternativa de código abierto a Firebase, pero basada en la potencia técnica de PostgreSQL. Cada proyecto en Supabase incluye una instancia dedicada de PostgreSQL con acceso completo a SQL avanzado, relaciones entre tablas y extensiones poderosas como PostGIS, Pgvector, pg_cron, y muchas más.

En términos prácticos, Supabase concentra en un solo panel los servicios de backend más comunes: gestión de base de datos, sistema de usuarios y autenticación, almacenamiento de archivos, generación automática de APIs (REST y GraphQL), y ejecución de funciones en el edge. Esto permite aprovechar la estabilidad de PostgreSQL junto con herramientas ágiles para acelerar el desarrollo.

Arquitectura de Supabase

La arquitectura interna de Supabase está basada en varios servicios open source que se comunican con la base de datos Postgres central. En la plataforma oficial, cada proyecto tiene su propia base PostgreSQL completa (sin abstracciones). Adicionalmente, Supabase integra varios servicios (GoTrue para Auth, PostgREST para APIs, Realtime, Storage, etc.).

Planes y Versiones Gestionadas

Supabase ofrece un modelo de servicio gestionado en la nube con diferentes niveles diseñados para acompañar el crecimiento de cualquier proyecto.

Free

$0 /mo

Ideal para proyectos personales, prototipos y aprendizaje.

  • 2 proyectos activos max
  • 50,000 MAU
  • 500 MB de base de datos
  • Pausa tras 7 días inactivo

$599 /mo

Modalidades de Despliegue: Ventajas y Desventajas

Plataforma Gestionada

Uso estándar en supabase.com administrado por el equipo oficial.

Ventajas

  • Configuración y escalado automático
  • Actualizaciones y nuevas funciones inmediatas
  • Alta disponibilidad y mantenimiento a cargo de Supabase

Desventajas

  • Dependencia del servicio externo
  • Costos atados al uso y tarifas en USD

Desarrollo Local (CLI)

Herramienta CLI para levantar localmente los servicios.

Ventajas

  • Desarrollo rápido y 100% gratuito
  • Trabajo offline y privacidad de datos total
  • Ideal para pruebas automáticas (CI/CD)

Desventajas

  • No apto para producción (stack no endurecido)
  • Sin servicios gestionados avanzados o dashboard web real

Self-Hosted

Instalación en propia infraestructura (Ej. Docker, AWS, GCP).

Ventajas

  • Soberanía total de datos para cumplimiento normativo
  • Sin tarifas mensuales de plataforma Supabase
  • Ajuste fino de hardware según escala exacta

Desventajas

  • Alta carga operativa (DevOps, backups, seguridad, caídas)
  • Sin branching, sin panel analítico y sin recuperaciones automáticas

Conclusión y Recomendaciones

Para proyectos en fase de prueba, prototipos o aprendizaje, el plan Free y el desarrollo local mediante CLI cubren las necesidades básicas sin costo. Conforme el proyecto escala hacia producción, el plan Pro (USD 25/mes) suele ser el paso más lógico, ya que proporciona recursos suficientes y reduce la carga operativa del equipo de desarrollo. Por otro lado, las empresas con requerimientos estrictos de seguridad y certificaciones encontrarán valor en el plan Team.

En la mayoría de los casos, la versión gestionada en la nube resulta ser la opción más práctica para delegar el mantenimiento de la infraestructura. El modelo Self-Hosted, aunque evita los costos de la plataforma, implica asumir la responsabilidad total de las operaciones (backups, monitoreo y actualizaciones), por lo que se recomienda principalmente cuando existen requerimientos técnicos o legales específicos que impiden usar soluciones de terceros.
